## Definition

Windows desktop app for listening to a large library of short-form spoken audio (audiobooks ~5min–1hr, a chapter at a time). Tauri 2 + React 18 + TypeScript + SQLite (rusqlite). **Read-only on audio files by default**; the rename tool is the sole sanctioned mutation.

- Repo: https://github.com/yovanmc/AudioShelf (default branch `main`)
- Design spec: [`docs/superpowers/specs/2026-06-11-audioshelf-design.md`](docs/superpowers/specs/2026-06-11-audioshelf-design.md)
- Detailed runbook (how-to, env, CI): [`docs/superpowers/WORKFLOW-execution.md`](docs/superpowers/WORKFLOW-execution.md)

## Conventions

- Cargo via `cmd /c "tools\dev-env.cmd cargo ..."` in the FOREGROUND (large timeout); `npm run build` before any `cargo tauri build`.
- Gates: `npx tsc --noEmit` · `npm test` · `cargo test` · `tools\verify.ps1 -Walkthrough <name>` (screenshot self-verification).
- Commits: use the repo's configured git identity (`yovanmc <yovanmc@users.noreply.github.com>`) — never pass `-c user.email=...` overrides. Follow the workspace `AGENTS.md`: substantive Codex-generated commits append `Co-authored-by: Codex <noreply@openai.com>` after a blank line.
- CI: `build-and-test` on windows-latest. Merge PRs `--merge --delete-branch` from main; FOREGROUND `gh pr checks <PR#> --watch`.
- App ships **no stylesheet** in v1 (intentionally unstyled).

## Decision log & gotchas

- **M16 (✅ shipped, PR #34) — v5's first migration & first backend milestone after the M8→M15 frontend streak:** all 8 sub-features delivered in one broad milestone across 13 tasks. **Execution: 6 Sonnet subagents (one per phase vertical slice: backend migration+commands+tests → API+view+FE tests), serialized because every backend task edits the same `db.rs migrate()` / `lib.rs` handler list / `commands.rs` (a shared working tree — no parallelism).** Controller spec-reviewed each migration's `db.rs` wiring + handler registration directly. **The migration framework is the durable artifact:** `migrate()` reads `PRAGMA user_version`, runs `if current < N { run_step(conn, N, body) }` per step; `run_step` wraps the body in BEGIN/COMMIT/ROLLBACK and bumps `PRAGMA user_version = N` atomically inside the txn (crash mid-migration → DB sits at last fully-applied version); `const LATEST` + an `INSERT OR REPLACE` `schema_version` sentinel; `pub fn open_at_version(v)` mirrors the steps guarded by `if version >= N` for upgrade tests (re-exported in `lib.rs pub mod testing`). **`PRAGMA user_version = N` can't be parameterized** → `format!` with the validated integer is correct/safe. Used `execute_batch("BEGIN"/"COMMIT"/"ROLLBACK")` on a borrowed `&Connection` (NOT `&mut`/`unchecked_transaction`) so callers keep passing `&conn`. Migrations v2–v5 are all ADDITIVE (new tables + `ADD COLUMN` with constant default) → **the MangaReader FK-off table-rebuild was never needed.** Legacy real DBs (v1 tables but `user_version=0` from the old `CREATE TABLE IF NOT EXISTS migrate()`) upgrade cleanly — step 1 re-runs `SCHEMA_V1` idempotently and sets `user_version=1` (tested). **Gotchas / decisions that mattered:** (1) **`lofty 0.21` already a dep** (scan duration + covers) → embedded-metadata ingestion added **NO crate**; `Cargo.lock`/`Cargo.toml` stayed byte-identical (verified via `git diff --stat`). (2) **Fixture generator (`gen-fixture`) uses `hound` (WAV PCM) and CANNOT write ID3/Vorbis tags**, so `apply_metadata`/diff logic is unit-tested with a seeded in-memory DB + constructed proposals, not real tagged fixtures — noted limitation, not a defect. (3) **`detect_series` has no multi-work numeric series in the fixtures** ("Cool Story" is one multi-chapter WORK; titles are non-numeric), so it's tested with a seeded author ("Cool Story"/"Cool Story 2"/"Cool Story 3"); in the live `m16` shot the series spine correctly renders nothing (conditional section). Series UX = **auto-detect-and-apply on author open** (idempotent via `UNIQUE(author_id,title)` + work_id PK; read-only-until-`apply_series`). (4) **Transcripts use `LIKE`, not FTS5** (plan's recommendation — adequate for a local library, zero new dep); `.srt`/`.vtt` are non-audio exts so sidecar ingestion never moves the 43/44/47 counts. (5) **A real gap the controller caught:** Phase 5's transcript components had optional props but **App.tsx was never wired** to call `searchTranscripts`/`getChapterTranscript` (subagent deemed it "not required") → a follow-up fix wired both (search bucket + Now-Playing panel) so the feature is live, not dead. **Lesson: when a subagent leaves "optional props" unpopulated, verify the App-level wiring exists or the feature won't render.** (6) `undo_metadata` deferred (proposals are ephemeral/re-derivable; re-scan+re-preview suffices). **Gate evolution:** cargo gate is now "all green + fixture 43/44/47" (the prior 47 grew to 95 unit + integration as new Rust tests landed); FE 210→248. Screenshot verify: new `m16` walkthrough (6 steps: manage-tags, metadata-diff, series-spine, transcript-search, forgotten-shelf, discover-reasons) + full `m12` regression matrix — Sonnet subagent text verdict **PASS** (sole cross-screen change is the new "Import tags" sidebar nav item). **NEXT: validate M17 (The Listening Journal) before planning — it's the next signature/schema milestone; re-confirm scope vs the v5 backlog.**
