## Definition

Windows desktop app for listening to a large library of short-form spoken audio (audiobooks ~5min–1hr, a chapter at a time). Tauri 2 + React 18 + TypeScript + SQLite (rusqlite). **Read-only on audio files by default**; the rename tool is the sole sanctioned mutation.

- Repo: https://github.com/yovanmc/AudioShelf (default branch `main`)
- Design spec: [`docs/superpowers/specs/2026-06-11-audioshelf-design.md`](docs/superpowers/specs/2026-06-11-audioshelf-design.md)
- Detailed runbook (how-to, env, CI): [`docs/superpowers/WORKFLOW-execution.md`](docs/superpowers/WORKFLOW-execution.md)

## Conventions

- Cargo via `cmd /c "tools\dev-env.cmd cargo ..."` in the FOREGROUND (large timeout); `npm run build` before any `cargo tauri build`.
- Gates: `npx tsc --noEmit` · `npm test` · `cargo test` · `tools\verify.ps1 -Walkthrough <name>` (screenshot self-verification).
- Commits: use the repo's configured git identity (`yovanmc <yovanmc@users.noreply.github.com>`) — never pass `-c user.email=...` overrides. Add trailer `Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>`. **No Codex trailer.**
- CI: `build-and-test` on windows-latest. Merge PRs `--merge --delete-branch` from main; FOREGROUND `gh pr checks <PR#> --watch`.
- App ships **no stylesheet** in v1 (intentionally unstyled).

## Decision log & gotchas

- **Grouping:** `original_stem` is threaded for on-disk file lookup; canonical `stem` drops trailing words. Lone numbered file demoted to standalone ("Area 51" not split into "Area"/51).
- **Asset protocol:** static scope `[]` + runtime `allow_directory(root, true)` in `scan_library` (library root only).
- **Harness:** `settle()` (double rAF + 60ms) before every screenshot; a walkthrough step that reads React state set by the immediately-prior step must be self-contained (re-fetch). Screenshots render on the user's iOS app via the Read tool.
- **Subagents** must run cargo in the FOREGROUND (background builds can't be resumed).
- **Windows:** a colon in a filename creates an NTFS Alternate Data Stream, not a real file (bit M4 tests).
- **Rename↔grouping (v1 limit):** `grouping_overrides` is keyed on `file_path`, so renaming an overridden file via M4 orphans its override row. Acceptable for v1.
- **Settings (M6):** library root persisted in the `settings` table under key `library_root`. The `--library` flag is intentionally **not** persisted (keeps the harness hermetic); only user-picked roots survive restarts. Native picker needs a **capability file** (`capabilities/default.json` granting `dialog:default`) — plugin commands are gated, unlike custom app commands.
- **Tauri debug rebuild gotcha:** `cargo tauri build --debug` is a no-op cache hit if no *Rust* source changed — even after `npm run build` updated the embedded `dist/`. A stale binary runs old JS and the harness hangs. Force a relink (`cargo clean`, or touch a Rust file) after a frontend-only change before re-running the screenshot harness.
- **v2 scope (decided 2026-06-12):** "Library Experience" = M8 covers, M9 work/chapter tags, M10 richer browsing UI. **Multi-root libraries explicitly deferred** (not chosen). Playback-side features (speed, per-second resume, auto-advance) deferred to a possible later v3.
- **M8 design (cover art):** Resolved **on-the-fly by command** (`get_work_cover` embedded-first, `get_author_cover` folder-image-first) — **NO schema change/migration**. The library is flat (`Author/file.wav`), and chapter `file_path`s are absolute, so an author dir = `parent(file_path)`; this sidesteps the harness-unset `library_root` setting. Thumbnails (`image` crate, max 256px) cached under `<app_data>/covers/` keyed by source path+mtime hash, served via the **existing asset protocol** (`allow_directory(covers, true)` granted in `setup`; `convertFileSrc` on the FE) — no `base64` crate needed. `<Cover>` lazy-loads w/ a module-level client cache and falls back to the color+initials `<Swatch>` (no layout shift). **Harness gotcha:** `settle()` (2 rAF + 60ms) does NOT wait for `<img>` decode → added `imagesSettled()` before cover screenshots. Fixtures use **folder `cover.png`** images (PNG via `image` crate) on Jane Doe + Sam Smith — non-audio, so `fixture_scan.rs` counts stay 43/44/47; embedded extraction covered by unit tests (`lofty` picture read).
- **M8 (✅ shipped, PR #8):** Covers resolved **on-the-fly by command** (`get_work_cover` embedded-first, `get_author_cover` folder-first) — **NO schema change/migration**, as planned. Author dir = `parent(file_path)` (chapter paths are absolute), deliberately avoiding the harness-unset `library_root`. Thumbnails (`image` 0.25, ≤256px, aspect preserved) cached under `<app_data>/covers/` keyed by hash(source path + mtime), reused if present; served via the **existing asset protocol** (`allow_directory(covers, true)` granted in `setup`, `convertFileSrc`/`fileUrl` on the FE) — **no `base64` crate**. `<Cover>` (in `src/components/Cover.tsx`, which now also owns the shared `<Swatch>` moved out of `LibraryView`) lazy-loads with a **module-level `Map` cache** (so virtualized rows remounting on scroll don't refetch) and falls back to the initials `<Swatch>` — no layout shift, no broken-image icon. **Harness gotcha:** `settle()` (2 rAF + 60ms) does NOT wait for `<img>` decode, so added `imagesSettled()` (resolves on each image's `load`/`error`) and capture does `settle()→imagesSettled()→settle()`. Fixtures drop a non-audio `cover.png` into Jane Doe (red) + Sam Smith (blue), so `fixture_scan` counts stay 43/44/47 (do not edit that test). The `image=0.25` dep added to `tools/gen-fixture` pulls ~975 transitive `Cargo.lock` lines — must be committed (a later cargo build can regenerate it post-commit; re-check `git status` before PR). New harness output dir `.shots-baseline/` is gitignored. Non-atomic cache write (write-not-rename) accepted for a local thumbnail cache. PR also carried a small `chore(harness)` commit: an informational tile-max pixel-diff helper (`tools/Compare-Screenshots.ps1` + `verify.ps1` manifest) — CHANGED/NEW shots never fail a run.
- **M7 (✅ shipped):** Search is a **backend** `search_library` SQL command (indexed `LIKE` w/ ESCAPE, per-bucket cap 50), debounced 150ms client-side — *not* client filtering (would defeat the 10k scale target). `LibraryView` is **fully controlled** by App (query + results props), staying free of `invoke`. Author list virtualized with **`react-window` `FixedSizeList`** (explicit height/itemSize → renders a bounded window even in jsdom, enabling a deterministic 1000-author bound test). Cover placeholders are **inline-styled** color+initials (app ships no stylesheet, so a CSS class would be inert). Fixture gained **40 `Zz Sample Author NN`** authors named to sort **after** the real three so first-author walkthroughs (player, grouping) are unaffected — regression-verified. **Gotcha:** the fixture-count integration test (`src-tauri/tests/fixture_scan.rs`) hardcodes author/work/chapter counts (was 3/4/7, now 43/44/47) — any future fixture change must update it. Substring search means querying `sam` also matches `Zz Sample Author NN` (the substring "sam" is in "Sample") — expected, not a bug. **`react-window` v1 only** (v2 has a breaking API). CI uses `npm ci`, so `package-lock.json` ships synced. **With M7 the v1 spec (design doc §4/§6/§13) is fully implemented.**
